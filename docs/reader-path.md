# Follow one planned handoff

[Back to the preview](../README.md)

Imagine a requirement changes for a routine handoff. The work includes revising a checklist and carrying out the handoff using that checklist. This example illustrates the proposed design.

1. **Specify the change.** Link the requirement, planned handoff, and checklist. State what needs to be verified before the handoff and what evidence would establish completion.
2. **Review the plan and checklist.** The reviewer can see the current versions and how they changed. A proposed revision names the version and scope it depends on. The design calls for a stale proposal to receive a refusal so it can be reconsidered against the current record.
3. **Carry out the handoff and verify the result.** Keep the review decision and verification evidence with the work. The design calls for evidence to identify the action and checklist version it covers. An uncertain outcome stays explicit.

The aim is to help a reader answer three questions. What was planned? What happened? What evidence supports the outcome?

For the design behind these steps, see [the target architecture](architecture.md).
